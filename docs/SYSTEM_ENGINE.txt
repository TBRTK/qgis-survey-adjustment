SURVEY SA2 - AZIMUTH CALIBRATION AND EXPLICIT SIGNAL PAIRS (0.13.0)

One existing raw catalogue, import, background queue, result/map/export flow and
baseline handoff. SA2 is a separate experimental engine contract (v4); upstream
v1/v2 and SA1 v3 jobs keep their own identities and historical numerical models.

SA2 uses the same pinned upstream source/compiler and own builder below, with
--variant sa2 and a NEW output directory. It extends the existing system_pcv.c,
not a second solver/import pipeline. Receiver arrays retain every PCO, NOAZI and
azimuth sample. Absolute ANTEX 1.4; zenith 0/90/5, DAZI=0 or 5-90 degrees dividing
360; complete clockwise rows 0..360 with identical seam values. Other grids or
ANTEX 2.0 are refused, not approximated. Bilinear interpolation uses antenna-frame
azimuth = (geodetic line-of-sight azimuth - NRP heading) mod 360. PCO N/E rotates
by that heading; marker-to-ARP H/E/N remains in local geodetic ENU and is separate.
No dropped azimuth terms, GPS-pattern fallback or universal 95 mm adjustment.

Each receiver must be level with constant documented NRP heading over the whole
occupation. Explicit mode and separate base/rover angles (0 <= angle < 360) are
required, together with orientation/provider-note review. 0 is true north and
90 east. Grid north, magnetic north, camera direction and travel direction are
not interchangeable. RINEX ZERODIR AZI must agree if present; PCVS APPLIED blocks
double correction. Changing yaw/tilt requires time-tagged body orientation and
another reviewed model; no IMU/visual-survey correction is implemented here.
Already tilt-corrected final coordinates still use the existing coordinate import.

Reviewed pairs: GPS L1/L2, GLONASS G1/G2, Galileo E1/E5a, BeiDou B1C/B3I.
Actual ANTEX IDs: G01/G02, R01/R02, E01/E05, C01/C06. C01 is 1575.42 MHz B1C
in the reviewed RS4P file; it is not 1561.098 MHz B1I/C02. No substitution.
SA2 changes the engine's observation slot mapping while preserving actual carrier
frequencies. Same common code/phase signal is explicitly selected at BOTH receivers
through existing RINEX options. GPS: 1C/P/W/L/S/X and 2W/P/C/S/L/X; GLONASS 1C/P,
2C/P; Galileo 1C/B/X and 5Q/I/X; BeiDou 1P/D/X and 6I/Q/X. Extra bands stay outside
this one/two-frequency profile. BeiDou requires unambiguous RINEX 3.03-3.05.
Galileo F/NAV clock/ephemeris selection is explicit; no I/NAV clock substitution.

GPS remains required. GLONASS AR stays off with the existing FDMA/nav checks.
RINEX-3 D1/D2 does not provide B1C broadcast code biases: SA2 therefore excludes
BeiDou from coarse absolute single-point initialization. Actual relative same-
signal receiver differences still use BeiDou; no missing absolute bias is invented.
The residual report includes genuinely valid relative observations even when a
satellite was excluded from coarse SPP. No PPP, precise products, CNAV/RINEX 4,
satellite antenna calibration, datum/epoch transformation or accuracy guarantee.

Application audit: per receiver/system/frequency PCO/NOAZI, NRP heading, DAZI,
EVERY azimuth sample, selected actual signal, satellite direction and applied range
correction. The adapter compares all values and independently recomputes that
correction (including H/E/N). Every selected system/frequency must contribute valid
residuals. Original/full subset/calibration/source/config/engine hashes retained.
Provider comments and SINEX code remain in the selected model/report; copied or
unverified model warnings are visible before processing. Full covariance, exact
height/XYZ export, correlated epochs and duplicate-occupation safeguards unchanged.

HISTORICAL SA1 PROFILE AND SHARED BUILD/RIGHTS REVIEW (0.12.0)

SURVEY SA1 — EXPERIMENTAL FOUR-SYSTEM RECEIVER CALIBRATION

Survey Adjustment 0.12.0 extends the existing Raw GNSS > PPK/static dialog.
There is one raw catalogue, network project, background queue, result/map/export
flow and baseline handoff. The engine-profile choice changes only processing.
Upstream EX jobs and their historical v1/v2 audits remain readable.

ENGINE REVIEW / CHOICE — 2026-10-20
Reviewed upstream RTKLIB EX release 2.5.1 and current main commit
50886e2fef3da7aa49fe87405cf52ff99972711d: receiver ANTEX reading still skips
non-GPS records; receiver correction arrays are shared across systems.
GREAT-PVT at 8bd3d231885ddde7a9268252a0b4fdec28ba4981 is a GPLv3 alternative
with multi-GNSS RTK/PPP, ANTEX and Windows binaries. It was reviewed as a candidate,
not integrated or claimed tested here. It uses a different configuration/output
contract; adopting it requires a separate full-covariance and processing audit.

This release instead builds a separately identified experimental extension of
pinned RTKLIB EX 2.5.1 commit 62d4677ed8425a4e2748c6d390b500d1afb493fc.
SA1 adds independent receiver arrays for GPS/GLONASS/Galileo/BeiDou, reads actual
constellation/frequency IDs and uses the observed satellite system for every
relative residual. It does not relabel Galileo/BeiDou patterns as GPS. Missing
receiver/system/frequency models fail. The engine prints an application audit
for each receiver/system/frequency; the adapter checks this against the selected
PCO/PCV values. The entire original/subset files and full engine hash are retained.
Upstream decoding, filtering, ambiguity processing, POS/covariance and downstream
review are reused. SA1 is not an official RTKLIB release or an independent GNSS
algorithm validation. The original upstream executable remains supported.

SELECTED PROFILE
GPS L1/L2, Galileo E1/E5b, BeiDou B1I/B2I, GLONASS G1/G2. One/two frequencies;
GPS required for initialisation. GLONASS ambiguities remain float: no unreviewed
inter-frequency-bias calibration or GLONASS integer fixing. Every observed Rxx
requires its own plausible navigation state and explicit integer FDMA channel
-7..+6, with navigation coverage within 30 minutes at every observed epoch.
The documented GPS-minus-UTC offset is used for the coverage comparison with
GLONASS navigation UTC. No zero-channel or nominal-wavelength fallback.
Each selected system must contribute valid engine residuals before acceptance.

Receiver ANTEX remains absolute version 1.4, DAZI=0, zenith 0/90/5. Exact antenna,
radome, serial-specific/generic selection and whole-occupation validity are
required for BOTH receivers. Required IDs are G01/G02, E01/E07, C02/C07, R01/R02
(first ID only in single-frequency mode). No C01/C02, E05/E07, radome or serial
substitution. Calibration does not repair undocumented header heights. Verify
H/E/N is marker-to-ARP and does not already include the phase-centre correction.
No satellite calibration, azimuth model, extra bands, precise products, VRS or
frame/coordinate-epoch transformation. Static/PPK epochs remain correlated;
one documented occupation is reviewed through the existing baseline importer.

BUILD / LOCAL EXECUTION
No compiler, engine binary or upstream source archive is distributed in the
plugin ZIP. The GUI never downloads/builds an engine. Reviewed source builder:
tools/build_system_engine.py and tools/system_pcv.c in this source repository.
Download the exact source archive and official Zig 0.15.2 separately, then run:
python -B tools/build_system_engine.py --source-zip RTKLIB-source.zip --zig zig.exe --output NEW_LOCAL_FOLDER
The script verifies source/compiler hashes, preserves upstream/SOFA sources and
notices, patches a NEW directory and writes build.log and PROVENANCE.json.
It normalizes only unsigned PE/COFF timestamps and CodeView GUID, not code/data,
so independent builds produce identical bytes. No signing/authentication implied.
