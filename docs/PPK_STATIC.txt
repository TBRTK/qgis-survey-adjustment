Survey SA2 adds azimuth calibration and E1/E5a, B1C/B3I pairs in the SAME dialog.
Select fixed level orientation, enter base/rover NRP headings and review antenna

WORKFLOW / REUSE
Network project > Raw GNSS / RINEX > PPK / static processing of existing sources.
The existing raw catalogue, background queue, project and POS/baseline review
are reused. No new top-level import or competing inventory. Raw observations
are processed by a separate local RTKLIB executable, never by SALSA directly.
SALSA/network quality and Norwegian delivery remain their established downstream
workflows, with their frame, covariance and endpoint requirements unchanged.

1. Import/review base OBS, rover OBS and broadcast NAV through Import GNSS file.
   Define the physical points and UTC acquisition session in the existing network.
   Select the three existing links in PPK/static; no second raw import.
2. Choose separately installed RTKLIB EX 2.5.1 Windows rnx2rtkp.exe. Its SHA256
   must match the reviewed version below. The plugin does not download/install it.
3. Choose Static relative for an occupied stationary point, or PPK kinematic for
   a moving receiver. Select one/two slots: GPS L1/L2, optional Galileo E1/E5b and BeiDou B1I/B2I.
   GPS is required; GLONASS/QZSS/SBAS/NavIC and other bands are excluded.
4. Enter independently documented FIXED base geocentric X Y Z in metres, frame
   and coordinate epoch evidence. Approximate header XYZ is never used as control.
   The network epoch is a coordinate epoch, not an observation date. Selecting
   ETRS89/WGS84 is a declaration, not a realised-frame or epoch transformation.
5. Review original header H/E/N offsets for both receivers. These are passed to
   the engine as E/N/U antenna offsets. Result coordinates refer to the declared
   marker endpoints. Select explicit uncalibrated processing, or local absolute
   ANTEX 1.4 receiver calibration for GPS only (details below). Correct an ambiguous
   header in a separately documented source, preserving the original.
6. Document base uncertainty, antenna endpoints, model, purpose and dependence.
   Scroll the review area down to confirm base, antenna, model and engine licence.
7. Run into a NEW LOCAL result directory. Original files and network records
   remain unchanged. Input checks/copying use the existing background queue;
   engine runs asynchronously, with Stop and a two-minute timeout. Cancellation,
   stale project/settings, changed inputs or invalid output prevent acceptance.
8. Inspect Report, Solution epochs and computed PointZ positions. Quality states
   remain visible. The original solution.pos retains complete engine covariance.
   epochs.csv includes GPST, ECEF XYZ and h on the WGS84 output ellipsoid. ECEF Z
   is not ellipsoidal or national height. No HREF/NN2000 transformation here.
9. A moving trajectory is not a set of stationary physical control points.
   Select an eligible FIX epoch representing a documented stationary occupation,
   then Review solution through existing baseline import. It opens the SAME POS
   review as other GNSS sources, with point/session/frame bindings and processing
   provenance. Confirm physical occupation, covariance/dependence and selected
   epoch explicitly. Nothing is imported automatically and nothing is averaged.
10. Save the network explicitly. One selected baseline is added with full original
   covariance and engine/config/raw-source provenance in the existing import audit.
   Reprocessing, another processing mode, another epoch or a relabelled session
   do not establish a new independent occupation. The duplicate gate rejects it.
   Keep alternative processing runs as separate results for review/comparison.

LEGACY UPSTREAM PROCESSING PROFILE (v1/v2)
Pinned Windows RTKLIB EX 2.5.1, GPS L1/L2, Galileo E1/E5b and BeiDou B1I/B2I
code and carrier phase, one or two slots, GPS required for initialisation, static
or kinematic relative forward filtering, continuous ambiguity resolution,
broadcast ephemerides, elevation mask 10-45 deg and fixed AR ratio 3-10.
No fix-and-hold, moving-base, single-point/PPP modes or automatic base averaging.
Observation sources must declare GPS time and the same documented GPS-minus-UTC
offset; source times are not rewritten. Broadcast/Saastamoinen atmosphere for
real sources. Atmosphere-off is allowed only for explicit synthetic projects.
Header H/E/N offsets applied. Optional GPS receiver PCO/PCV as described below.
No satellite antenna calibration, tide correction, precise products, frame/epoch
shift or network RTK/VRS. BeiDou ambiguity fixing is off; float contribution is
retained alongside GPS/Galileo. No GLONASS ambiguity/bias calibration is claimed.
Every selected constellation must contribute valid engine residuals. Missing
contribution rejects the result instead of silently downgrading the selection.
The engine can decode more formats; the plugin only enables this tested profile.
The existing RINEX size/epoch/project limits and 10000 POS epoch limit apply.

Static output retains every correlated filter epoch, with its actual timestamp.
The selected final eligible state can represent the static occupation after
review; the plugin does not compute a mean or reduce covariance by sqrt(n).
The PPK trajectory similarly retains all states and quality flags. FIX is an
engine ambiguity status, not an accuracy guarantee. Formal covariance excludes
base-coordinate, frame, antenna, multipath and common errors. No independent
raw GNSS algorithm cross-check or field/delivery certification is claimed.
Base/orbit plausibility and catalogue checks are screening only; orbit health,
validity, usable geometry and ambiguity behaviour still need professional review.

RECEIVER CALIBRATION / ENGINE LIMIT
Choose Receiver ANTEX, a local absolute ANTEX 1.4 file and source/version/usage
rights/installation evidence. Both RINEX headers must contain exact IGS model
(16 columns) plus radome (4 columns). Selection requires the complete observation
interval within VALID FROM/UNTIL in GPS time. An exact serial-specific model
takes priority; otherwise one generic type/radome record is allowed and reported.
Ambiguous or absent matches fail; no different radome/serial is silently used.
Both receivers need PCO and 19 NOAZI PCV values for G01 (and G02 for two slots).
Only DAZI=0 and ZEN1/ZEN2/DZEN=0/90/5 are enabled. Other grids, azimuth-dependent
patterns, relative models, unsupported precision and ANTEX 2.0 fail explicitly.
North/east/up ANTEX millimetres are preserved; H/E/N RINEX metres remain separate
marker-to-ARP offsets. Verify antenna orientation, mounting and physical ARP.

The pinned engine readantex() skips non-GPS receiver frequency blocks, antmodel()
has shared frequency slots, and searchpcv() permits radome fallback and ignores
receiver serial/validity. The plugin therefore selects strictly BEFORE execution,
writes two unique aliases containing only the exact selected numerical models,
enables receiver PCV explicitly, and preserves/hashes original and engine subset.
It refuses ANTEX combined with Galileo/BeiDou. Multi-GNSS is explicitly
uncalibrated. Supporting constellation-specific receiver calibration requires a
different reviewed engine contract, not relabelling GPS frequency blocks.
This calibration does not establish field accuracy or repair incorrect heights.
No calibration datasets are downloaded, bundled or published; users retain their
data provider's rights/attribution obligations. Invented examples are own data.

LOCAL RESULT / INTEGRITY
processing.json: pending/completed/aborted state, fixed profile, engine identity,
options, original/copy source SHA256 and fingerprints, base/point/session/frame/
epoch, model/antenna review, configuration and output hashes.
network.sanet.json: unchanged input network snapshot; base/rover/navigation.rnx:
decoded copies used by the engine; processing.conf: exact submitted options.
solution.pos: original engine output, including full signed covariance roots;
solution.pos.stat: engine state/residual log, when produced; console.txt: bounded
engine log; epochs.csv and report.txt: local readable exports.
With ANTEX, original.atx and receiver.atx retain original and selected models.
The v2 processing audit records systems, frequency count and full selected
calibration. Existing v1 GPS jobs and import audits remain readable.
These contain private paths/measurements. Keep them local, outside publication.
Keep the complete result directory to retain its provenance. Reopening the POS
through the existing importer verifies completed state, copies/configuration and
output hashes. Missing/tampered/stopped packages are refused. The selected raw
links cannot be deleted/relabelled after importing their dependent baseline.
Hashes are integrity checks, not a signature, authenticity or scientific proof.

CONSTRUCTED EXAMPLES
Choose mode, satellite systems and calibration, then New synthetic example. This creates a NEW
network with two physical IDs, one session and three raw links in a new local
folder. It never overwrites an existing network. Review confirmations remain off.
The generator constructs 24 ideal circular orbits per selected system, visible signals,
integer carrier ambiguities, reproducible code/phase noise and a ten-minute
stationary or moving receiver, with independent known coordinate truth.json.
No atmosphere is deliberate. Uncalibrated examples have zero antenna offsets.
ANTEX examples instead inject invented nonzero north/east/up PCO, NOAZI PCV and
base/rover H=1/2 m. Applying the matching models recovers physical marker heights;
omitting them leaves a measurable bias in this constructed integration test.
Moving example changes ECEF X by 12 metres over ten minutes. Original 0.9 parser
fixtures contain nonphysical zero ephemerides and are explicitly refused here.
Survey SA1 examples also construct GLONASS rotating-Earth/J2 state vectors and
FDMA carrier frequencies, plus distinct per-system/per-band antenna models.
No receiver/reference-station or customer data are bundled. Synthetic tests
demonstrate the engine/GUI/import/export path, not real survey accuracy.
