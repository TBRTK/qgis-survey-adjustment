EMLID REACH RS4 PRO - SUPPORT STATUS, SURVEY ADJUSTMENT 0.14.0

0.14.0 adds ETC orientation/pole-tip coordinate review inside the existing dialog.
This is a coordinate supplement; full dynamic raw ANTEX/carrier processing remains
blocked. See ORIENTATION.txt for 34.8 research, logging, heights and exact limits.

The plugin remains receiver independent and processes documented exported data.
It does not control receiver firmware/radios, camera/visual survey, AR or IMU tilt.
Full device support and receiver-specific field accuracy are NOT claimed.
Processed coordinate/CSV review and raw RINEX processing are separate workflows.
Do not subtract antenna height again from final exported ground coordinates.

NEW IN 0.13.0
The existing PPK/static dialog has a separate experimental Survey SA2 engine
choice. It reads complete azimuth-dependent absolute ANTEX 1.4 grids for the
exact antenna/radome and serial/generic model, valid for the whole occupation.
DAZI=0 or a step of 5-90 degrees dividing 360; zenith 0/90/5. Missing samples,
inconsistent 0/360 seam and unsupported grids fail, not reduced to NOAZI.
Original/subset hashes and every numerical model value are retained/audited.

Selected pairs: GPS L1/L2, GLONASS G1/G2, Galileo E1/E5a and BeiDou B1C/B3I.
The actual IDs G01/G02, R01/R02, E01/E05 and C01/C06 match the corresponding
bands in the reviewed RS4P file. Its own frequency table specifies C01 as
1575.420 MHz and C06 as 1268.520 MHz. C01 is NOT B1I/C02 at 1561.098 MHz.
Other RS4 Pro signals, including GPS L5, are outside this one/two-slot profile.
There is no E05/E07, C01/C02, antenna/radome or RS4/RS4P substitution.
The engine keeps the real carrier frequencies and forces the same documented
code/phase signal at both receivers. Galileo uses the reviewed F/NAV clock
profile; BeiDou B1C requires RINEX 3.03-3.05, without ambiguous older identifiers.
See SYSTEM_ENGINE.txt for B1C coarse-SPP bias limits and all processing bounds.

OFFICIAL MODEL QUALIFICATION
The NGS catalogue reviewed on 2026-10-20 has separate EML_REACH_RS4 NONE and
EML_REACH_RS4P NONE entries. The RS4P entry is DAZI=5 and explicitly labelled
as copied from RS4 without verification by calibration. This qualification is
part of the source model, not proof of an independent RS4 Pro calibration.
It is preserved in the selection/audit and shown in the antenna review/report.
Use the exact RS4P entry; never silently select RS4. Accepting its format/numbers
does not remove the provider qualification. Real antenna files remain local,
outside plugin ZIP and GitHub distribution.

ORIENTATION - REQUIRED FOR RAW AZIMUTH CALIBRATION
Select fixed, level orientation and enter separate base/rover antenna NRP
azimuths, clockwise from true/geodetic north: 0 north, 90 east. Locate the NRP
using the actual antenna diagram. Do not infer it from a camera, grid north,
magnetic north or direction of travel. A RINEX ZERODIR AZI declaration must
agree if present. Antennas must keep that heading and remain level throughout
the selected occupation. PCO is rotated in the horizontal plane; PCV uses
satellite azimuth relative to the antenna NRP and bilinear grid interpolation.

Changing yaw/tilt is an explicitly unsupported choice and blocks SA2 processing.
Dynamic corrections need time-tagged body orientation, axis/frame definitions,
lever arms and independently tested alignment/time synchronization. An IMU-
equipped receiver or a GNSS track alone does not provide those inputs here.
Already tilt-corrected final points can use the existing coordinate import;
they are not reprocessed with a second raw antenna/tilt correction.

HEIGHTS AND REMAINING DEVICE VALIDATION
Emlid distinguishes mark-to-ARP height and ARP-to-phase-centre offset. Flow
adds a model-dependent offset; the published Studio workflow describes manual
handling. Its Studio-specific 95 mm example must not become a universal plugin
addition. Review actual RINEX H/E/N, antenna name and whether PCO is already
included. The plugin keeps H/E/N and exact per-frequency PCO/PCV separate.
RINEX declarations of already-applied PCV block double calibration.

Emlid recommends RINEX 3.03 if the required export version is unknown. Firmware
version alone does not validate signal/height/header semantics. Actual paired
base/rover OBS, matching NAV, antenna/radome/NRP and pole/ARP evidence, logging
settings, times/UTC offset, frame/epoch and independently known base/check point
are still needed for device-specific end-to-end checks. Preserve originals and
keep customer data private. UBX/NMEA/RTCM direct raw imports and RINEX 4/CNAV
are outside this profile. Generated examples are invented integration tests.
