NEW IN 0.17.0 - EXPLICIT GLOBAL STATIC / NATIONAL CHECK
The existing static GNSS dialog now accepts explicitly documented ITRF2020
ECEF coordinates with a separate v6 GPS L1/L2 engine-clock audit. Pinned RTKLIB
pntpos.c corrects solution time by the receiver clock; each solution is linked
to exactly one original RINEX epoch using the recorded $CLK correction and only
the documented millisecond output quantization. Original times are preserved.
clock_epoch_audit.csv is recalculated on readback; legacy v1-v5 remain unchanged.

The SAME dialog can compare one selected fixed OR float epoch with its existing
known Check point. An explicit actual coordinate epoch and national EUREF89/height
review are required. A pinned local ITRF2020-to-ETRS89-NOR operation uses reviewed
NKG grids; existing projection/HREF code supplies the final height reference.
Differences and model/source hashes are saved in a separate local comparison;
raw POS, covariance, point coordinates and inventory remain unchanged. Global
vectors remain global and cannot enter the ETRS89-only network adjustment.

IGc20 use requires external evidence of its zero alignment to ITRF2020. This is
not an arbitrary IGS/WGS84 adapter. Output covariance is NOT propagated, and a
coordinate difference or FIX flag is not accuracy or delivery approval. Exact
antenna/radome selection and documented H/E/N remain required. A user-approved
NOAZI approximation must be explicit, with original provider grids/comments and
omitted terms retained locally; unknown heading is never invented. No general
NOAZI conversion, precise SP3/CLK, VRS generation or dynamic tilt is added.

For comparison, keep the rover as a known Check point in the existing network.
Process in ITRF2020 ECEF at the documented base-coordinate epoch, select ONE
solution epoch, then Compare selected ITRF2020 epoch with known EUREF89 point.
Review the actual global coordinate epoch as decimal year, national control
reference and explicit height version. Supply the reviewed local HREF GeoTIFF
for NN2000. The two reference grids must already exist in the local PROJ data
directory and match the pinned SHA256 in delivery.GlobalReferenceOperation.
There is no automatic download, ballpark or missing-grid fallback. Use the
existing result report to compare E/N/height and retain both FIX and float state.
The local reference_comparisons folder is separate from original engine output.
The reported difference is computed minus known, in the declared projected axes.
Known control uncertainty and transformed solution uncertainty are not inferred.

The v6 initial profile is upstream EX, static GPS L1/L2 only. GPS clock bias must
be finite and within 100 ms. The POS and $CLK status epoch/quality must match.
t_solution = t_recorded - GPS_clock_bias; $CLK units are nanoseconds. Only the
0.001 s written POS/stat rounding and 0.001 ns written clock rounding are allowed
when reconstructing the unique original epoch. Missing, duplicated, inconsistent
or ambiguous evidence blocks acceptance. Original RINEX timestamps never change.
The CSV is recalculated from the original source epochs/status on each readback.
Legacy v1-v5 jobs retain their original checks and do not silently opt into v6.

Survey Adjustment 0.8.0 / QGIS 4

Open Network project -> Norwegian reference review / delivery package.
Or open Norwegian reference review / delivery after a verified GNSS-network
or mixed-survey SALSA calculation. A preview without SALSA is not accepted.
Use the separately installed, unchanged solver used for the calculation.
Opening a completed run validates hashes, independently reproduces the model
and checks SALSA output without executing the solver or rewriting the run.

QUICK START
1. Finish a GNSS-network or mixed-survey calculation with Run SALSA and verify.
2. Open the delivery workflow; select the completed folder's quality.json.
3. Declare the actual input height basis. Legacy NN2000 requires an explicit
   NN2000:2018 or NN2000:2025 choice, supported by project documentation.
4. Choose the output UTM 31-36 or NTM 5-30 projection and height reference.
5. Fill the reference evidence, reviewer, recipient/specification, purpose,
   uncertainty review and manual change/exclusion log. Help appears beside
   each field. The reviewer field records a statement, not a certification.
6. For a height conversion choose the required local, reviewed HREF GeoTIFF(s).
   Retaining a height reference applies no HREF at all.
7. Read and select the explicit review confirmation. Check references / preview
   delivery shows source, adjusted and delivered coordinates, acquisition
   times, reference choices, operations, offsets and limitations.
8. Create local delivery package in a selected existing parent folder.
   Every delivery uses a new folder. Original inputs/results are preserved.
9. Check an existing delivery package verifies file hashes, CSV contents,
   PointZ coordinates/heights and horizontal/vertical reference metadata.

REFERENCE EVIDENCE
Input E/N must already be in the national EUREF89 realisation. This workflow
does not turn a WGS84/ITRF label into EUREF89, or prove reference identity from
coordinate magnitudes. Document the control source and any prior transformation.
The original CRS identifier and full calculation provenance remain unchanged.
UTM/NTM output uses explicit GRS80 inverse/forward projection formulas, never
an automatically selected frame-shift operation. E/N are always Easting then
Northing, metres. Z is point/mark height, positive upward, in the stated basis.

The coordinate epoch is the date recorded in the original calculation snapshot.
Explain its source in Epoch evidence. Acquisition-session times are recorded
separately in UTC. An observation date, a receiver filename and a reference-
frame anchor epoch are not interchangeable. No deformation/time-dependent
transformation or coordinate re-epoching is implemented here. If the original
epoch is wrong, correct a separate network snapshot with documented evidence
and recalculate; do not relabel a completed run as another epoch.

Document antenna/mark reference points and reductions in Height evidence.
An NN2000 input is not an ellipsoidal input; do not subtract HREF twice.
NN54 and LOCAL heights may be retained, but cannot be converted in this profile.
LOCAL heights have explicit attributes; no national vertical CRS is assigned.

HREF MODEL SELECTION
Kartverket's guidance reviewed 2026-10-20 identifies HREF2025A as official from
2026-10-14, with the output label NN2000:2025. HREF2018B produces NN2000:2018.
The change affects parts of western/southern Norway. Established projects may
need their existing model for continuity; document the recipient's selection.
Do not switch models silently. Guidance and coverage:
https://www.kartverket.no/til-lands/posisjon/href-hoydereferansemodeller-og-transformasjonsmodeller

Obtain models separately from the official source; choose local files in the
dialog. Some QGIS installations include the exact 2018 model in share/proj.
No model is bundled with the plugin ZIP and the plugin never downloads one.
A matching filename or a user-entered hash cannot approve unknown model bytes.
Supporting another conversion/version requires a reviewed code/registry update.

For each required model PROJ uses a mandatory, exact local vgridshift operation.
The correction is independently checked by GDAL bilinear raster interpolation.
H = h - N; h = H + N. Conversion between the two NN2000 versions goes through
ellipsoidal height using both models at the same horizontal position.
Missing/changed grids, no-data corners, points outside interpolation coverage,
non-finite results or disagreement stop export. There is no constant offset,
optional-grid, network-grid or ballpark fallback. Mainland profile bounds do
not prove coverage; the individual grid is checked too. Svalbard and offshore
extrapolation are not supported. Roundtrip agreement is a transfer check,
not independent proof of a model's field accuracy.

The installed CRS database may predate EPSG:11394. The exporter supplies an
explicit vertical WKT for NN2000:2025 (EPSG:11394 / datum EPSG:1454) in that
case. It does not substitute NN2000:2018. Actual conversion always uses the
selected hash-verified grid. Full source/output projection formulas, model
identity and runtime versions are retained in the delivery metadata.

CONTENTS AND AUDIT SCOPE
delivery.json: declarations, acquisition times, coordinate epoch, full review,
manual change log, model sources/hashes, runtime versions, operations, exact
source/adjusted/delivered coordinates, warnings and synthetic/real classification.
coordinates.csv: the three coordinate stages with explicit source/output CRS,
height references, coordinate epoch, synthetic flag and uncertainty limitation.
coordinates.gpkg: source_points, adjusted_points, delivery_points, all PointZ;
height/epoch metadata remain attached. A held-out CHECK without an adjusted
position stays outside the delivery-point layer, never promoted to a fitted point.
calculation/: the original, unchanged recorded source snapshot, measurements,
weights/covariance, settings, exclusions and reasons, engine/input/output evidence
and reports. The solver executable and its dependencies are not copied.
models/: the exact HREF files used, for local reproducibility, with attribution
and license links in delivery.json. No model is copied if none is applied.
delivery.txt/html: readable review, scope and limitations.
checksums.json: exact members and SHA256; added/missing/changed files are rejected.
LICENSE, NOTICE.txt, DISCLAIMER.txt: plugin rights and qualified AS IS notice.

The package is created under a new .incomplete directory and is renamed only
after readback succeeds. Failed output must remain marked incomplete. Reopening
a package for integrity checking never executes a solver or arbitrary content.
Checksums are not signatures: someone able to rewrite every file and manifest
can create another internally consistent package. Verification does not prove
authorship, chain of custody, recipient acceptance or professional survey approval.
The manual change log complements the saved snapshot; historical edits predating
that snapshot cannot be reconstructed or independently verified by this plugin.

UNCERTAINTY
The original report preserves the full fitted covariance and stated assumptions.
Delivered-coordinate covariance is NOT propagated through projection/HREF, and
model uncertainty is not guessed. No output sigma/accuracy is manufactured.
Assess model/reference/epoch/control errors and dependence separately before
professional use. A successful conversion and matching file readback do not
certify positional accuracy. Statistical warnings in the original report remain.
